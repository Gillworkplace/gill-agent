## 1. 项目背景与目标

### 1.1 背景

大模型 Agent 工具（如 Codex CLI、Claude Code）已证明"对话式驱动计算机完成任务"的产品形态，但现有产品要么是本地终端工具（无浏览器界面、无多人服务化能力），要么是云端 SaaS（不可私有化、无法接入企业内部系统）。本项目构建一个**可通过浏览器远程使用、也可通过 CLI 本地使用的私有化 Agent 服务平台**，并以沙箱保证执行安全。

### 1.2 产品定位

一句话：**"一群人围着一个共享沙箱，看着同一个浏览器画面，和同一个会越来越懂你们的 AI 一起写代码。"**

五个产品支柱（D11+D12）：

1. **多人协作开发（首要定位，D12）**：协作空间以群组为单位共享一切工作资源（沙箱/文件/浏览器/知识库/扩展），多人同时在线同一会话，实时同步对话流、终端与浏览器画面；配套操作权、协作感知与组内权限。
2. **完整的双端产品**：Web 工作台（对话/终端/浏览器预览/文件/知识库/扩展中心）与 Agent CLI（`gill`）功能对等、数据互通，覆盖"浏览器使用"与"终端集成"两类习惯。
3. **持续学习的知识库**：Agent 在对话中不断沉淀用户/群组偏好、项目知识、纠错记录，形成越用越懂团队的长期记忆（个人+群组双作用域）。
4. **极强的扩展性**：用户可通过五层机制扩展 Agent——自定义 HTTP 工具、脚本工具、技能（Skills）、MCP 服务器、提示词/人设；扩展可个人私有，也可发布到群组共享。
5. **安全与治理底线**：一切执行落沙箱（E2B 兼容）、多租户+空间级隔离、审批档位、命令审计与基础监控（简化实现，不为治理堆功能）。

### 1.3 目标与非目标

**目标（一期）**：交付 D1 三条验收 + 双端完整功能 + 知识库 + 扩展体系；单部署支撑 3 并发沙箱会话（沙箱机规格内），架构按 50 并发与多副本预留。
**非目标**：公共 SaaS 多租户运营能力（计费/多组织）、公网域名与 HTTPS、移动端原生 App、治理深度（复杂报表/归档/告警体系）。

### 1.4 竞品与规范对标（"遵循当前常见规范"的依据，D11）

| 对标对象 | 借鉴 | 差异化 |
|---|---|---|
| OpenAI Codex CLI | 交互范式（流式输出、审批档位 suggest/auto-edit 概念、会话恢复）、简洁命令风格 | Codex 为 Rust/TS 本地工具；gill 为 Python 双端（Web+CLI）服务化产品，执行全落沙箱 |

## 2. 术语表

| 术语 | 定义 |
|---|---|
| 工作空间（Workspace/Session） | 一个用户会话对应的隔离执行环境：专属沙箱（独立文件系统 + 独立 Chromium）+ 会话历史 + 工作区文件 |
| CubeSandbox（Cube） | 腾讯云开源 AI Agent 沙箱服务（KVM MicroVM，E2B SDK 协议兼容），本项目"e2b 沙箱提供方" |
| E2B SDK | e2b 官方 Python SDK；经 `E2B_API_URL` 指向 Cube |
| MinIO | S3 兼容开源对象存储，承载用户文件、导出物与备份 |
| 预签名 URL | MinIO/S3 带签名限时 URL，用于浏览器直传/下载 |
| RBAC | 基于角色的访问控制（USER / ADMIN） |
| CDP / Screencast | Chrome DevTools Protocol；`Page.startScreencast` 以 JPEG 帧流输出页面画面 |
| agentd | agent 服务常驻进程（FastAPI），Agent 推理与工具执行的核心 |
| Agent CLI（`gill`） | agent 服务命令行形态，与 web 共用同一账号/会话/知识库/扩展 |
| 事件总线 | web↔agentd 间的 Redis Streams/Pub/Sub 通道（多节点扩展基础） |
| 任务（Task）/ 轮次（Round） | 用户一次输入触发的执行单元 / 任务内一次 LLM+工具循环 |
| 审批（Approval） | suggest 档下敏感命令执行前的人工确认 |
| 魔数（Magic Bytes） | 文件头字节特征（MZ/ELF/OLE2 等），防扩展名伪装 |
| lease | Redis 中标记某 agentd 副本独占处理某会话的带 TTL 锁 |
| RTT | 本机→沙箱机网络往返延迟 |
| **知识库（Knowledge Base）** | Agent 的长期记忆存储：按 user/project/session 三级作用域组织的知识条目集合 |
| **知识条目（Knowledge Item）** | 知识库最小单元：类型（偏好/事实/纠错/项目知识/片段）+ 内容 + 标签 + 来源 + 置信度 |
| **沉淀（Capture）** | 将对话中的有价值信息写入知识库的过程（Agent 自动 or 用户显式"记住"） |
| **混合检索** | 向量（pgvector + 智谱 embedding）与关键词/标签检索加权融合的知识召回方式 |
| **技能（Skill）** | 以 `SKILL.md` 目录规范打包的扩展：指导文档 + 可选脚本资源，Agent 按需自动选用或用户显式调用 |
| **SKILL.md / GILL.md** | 技能描述文件 / 项目级说明文件（注入 Agent 上下文，约定同 AGENTS.md 生态） |
| **自定义工具（Custom Tool）** | 用户声明的扩展工具：HTTP 工具（表单/OpenAPI 定义）或脚本工具（Python+参数 Schema） |
| **MCP** | Model Context Protocol，业界标准的模型-工具连接协议；用户可挂载外部 MCP Server 扩展工具面 |
| **manifest.toml** | 扩展包声明文件：名称/版本/类型/权限/参数 Schema |
| **扩展中心** | Web 中管理扩展（安装/启停/配置/卸载）的页面 |
| **设计 token** | 前端设计系统的原子变量（色彩/间距/圆角/字号），支撑亮暗双主题 |

### 3.2 用户故事与使用场景（25 个，按主题分组）

> 每条格式：**背景 → 操作流程 → 系统行为 → 验收要点**。US 编号供测试用例引用。

#### 主题 A：新手旅程（Onboarding）

**US-01 首次注册到完成第一个任务（黄金 5 分钟）**
背景：新用户潘达注册后第一次进入工作台。
流程：①注册登录 → ②工作台展示引导横幅（三步卡片：发一个任务 / 上传一个文件 / 看浏览器画面），点击示例任务"帮我看看 example.com 首页说了什么" → ③Agent 打开浏览器，右侧预览出现画面，返回页面摘要。
系统行为：引导卡片可跳过且记忆"不再显示"；示例任务自动创建标题为"示例任务"的会话；首任务触发沙箱懒创建（提示"沙箱启动中…"）。
验收：从登录到看到结果 ≤2 分钟、≤3 次点击；引导不遮挡核心操作。

**US-02 空状态引导**
背景：新用户无任何会话/文件/知识。
流程：进入工作台 → 各面板呈现空态（插画+一句话说明+行动按钮："新建会话""上传文件"；知识库空态解释"Agent 会在对话中自动记住重要信息"）。
验收：所有列表/面板空态全覆盖（FR-125），文案口语化、无术语堆砌。

#### 主题 B：数据分析

**US-03 上传 CSV 分析并下载结果**
背景：潘达每月要汇总销售 CSV。
流程：拖拽 sales.csv 进对话流 → 系统完成直传并显示文件卡片 → 潘达输入"按月汇总金额，画柱状图，图里用中文，导出 png 和汇总 xlsx" → Agent 自动 materialize 文件进沙箱 → 终端滚动 pandas 命令 → 文件区出现 result.png / summary.xlsx → 点击下载。
系统行为：拖拽即上传（复用预签名直传）；Agent 调用 `workspace_files`/`materialize` 自动使用上传件；产物自动导出到 MinIO 并给出一键下载；全程右侧无浏览器画面（未用到浏览器）。
验收：全链路无报错；下载文件内容正确；终端输出实时可见。

**US-04 多轮迭代修正**
背景：潘达觉得图表颜色不对。
流程：输入"把柱子换成品牌蓝 #2F6BFF，标题改成 10 月汇总" → Agent 基于同一沙箱（数据仍在）重绘导出 → 文件区版本更新。
系统行为：会话内文件系统与浏览器状态跨消息保留（FR-22）；同名导出覆盖并记录版本。
验收：第二轮不重新上传/重新读文件即可完成；新旧文件可对比下载。

**US-05 Excel 公式级问题**
背景：潘达问"这个表里 D 列和 F 列对不上，帮我找差异行"。
流程：Agent 在沙箱用 pandas 比对 → 输出差异表（markdown 渲染）→ 潘达点"保存为 xlsx"（消息内代码块/表格的快捷操作）。
验收：消息内表格支持"保存到工作区"操作；差异结果正确。

#### 主题 C：网页自动化

**US-06 信息采集**
背景：何姐要查 10 个竞品官网的客服电话。
流程：输入"打开这几个网址（列表），逐个找到客服电话，汇总成表格：[urls]" → Agent 依次导航 → 右侧预览实时切换画面 → 何姐全程可见 → 返回 markdown 表格 + 可保存 xlsx。
系统行为：浏览器工具串行执行；每步导航在预览同步（≤2s 变化）；结果表格可保存。
验收：≥8/10 准确提取（以人工核对为准）；画面无长时间黑屏/卡死。

**US-07 用户中途接管**
背景：Agent 填表单时选错了省份。
流程：何姐直接在右侧预览里点击下拉框选对省份 → 输入正确内容 → 继续。Agent 感知页面状态变化（下一步操作前 browser_read_page 重新确认）。
系统行为：用户交互与 Agent 操作共用同一浏览器（互不踢线）；Agent 下一步以页面实际状态为准。
验收：用户点击/输入即时生效且画面同步；Agent 不覆盖用户刚才的选择。

**US-08 定期监控脚本**
背景：陈码要每天检查一个页面上"维护公告"是否出现。
流程：让 Agent 写一个检查脚本存到工作区 → Agent 提示"可以在 CLI 用 gill run 每天跑" → 陈码将脚本提交到公司 cron。
系统行为：脚本工具产物可保存；提供 CLI 化运行路径（FR-116）。

### 3.3 边界场景（必须支持）

- 任务执行中关闭浏览器标签 → 会话与沙箱按空闲 TTL 保留，任务在服务端继续跑完并落库，重连可回看结果。
- 弱网（RTT>200ms）→ 投屏自适应降档，交互回注仍有效（延迟容差提示）。
- 两个标签同账号同会话 → 都能收流；输入双方可见。
- 沙箱冷启动/全局排队 → 明确等待态与队列位次提示（§11.2.4）。
- 知识库为空/检索无命中 → 不注入任何内容，Agent 正常工作，不暴露内部机制。
- 扩展工具调用失败（网络/超时/4xx）→ 工具结果返回错误信息，Agent 向用户说明并建议，任务不崩溃。
- MCP 服务器离线 → 扩展中心标红，Agent 不再列出其工具，其余功能不受影响。
- 协作边界（v1.4）：成员被移除瞬间其 WS 断开且历史不可见；同一浏览器在自由模式下多人并发输入 → 服务端按到达顺序串行化回注，画面事件不丢失；持令者掉线 → 令牌 30s 后自动释放可被申请；会话满员（同会话在线 >10 人）→ 新观看者提示"已满，稍后进入"（NFR-14）。

## 7. 关键技术事实与约束（澄清结论）

- **F1（已确认）**：CubeSandbox 无法安装在本机 Windows Docker 容器内。部署于沙箱专用机 **39.107.34.109**（PVM 路径，实测达标见 D9），本地容器经 `E2B_API_URL=http://39.107.34.109:3000` 接入。
- **F2：E2B 接入已验证**：e2b Python SDK 经 `E2B_API_URL / E2B_API_KEY / CUBE_TEMPLATE_ID / CUBE_PROXY_NODE_IP` 切换至 Cube。
- **F3：沙箱模板**：官方 `sandbox-code` 兜底；自建 `gill-browser`（含 Chromium + CJK 字体，expose-port 9222）。
- **F4：LLM**：智谱 GLM OpenAI 兼容接口（chat + embedding-3 向量）；key 仅存 agentd 环境；模型名可配置。
- **F5：代理**：容器内用 `http://host.docker.internal:7890`（需 Allow LAN）；`NO_PROXY` 排除内网、沙箱机与 ACR。
- **F6：浏览器画面**：CDP `Page.startScreencast` JPEG 帧流，不引入 noVNC。
- **F7：语言边界**：web=Java 21 + Spring Boot 3；agent=Python 3.12（FastAPI+e2b+openai SDK）；CLI 参考 codex 交互范式。
- **F8：中间件**：PostgreSQL 16（+**pgvector** 扩展承载知识向量）+ Redis 7（总线/锁/限流）+ MinIO（uploads/exports/backup）。沙箱无法直连本地 MinIO，进出沙箱由 agentd 流式中转。
- **F9：镜像仓库**：阿里云 ACR，沙箱模板镜像 `registry.cn-guangzhou.aliyuncs.com/gill-gplatform/gill-agent-sandbox`（私有，沙箱机需 docker login）。
- **F10：MCP 生态（新）**：一期接入远程 MCP（SSE/Streamable HTTP）；stdio MCP 在沙箱内经 npx/uvx 拉起列 P1，接口按 MCP 标准实现，不自造协议。

### 11.3 认证与会话规格

#### 11.3.1 字段规则

| 字段 | 规则 | 错误码 |
|---|---|---|
| username | 3–32 字符 `[a-zA-Z0-9_-]`，唯一（忽略大小写） | AUTH-1002 |
| password | ≥8 字符且含字母数字两类，≤64 | AUTH-1003 |
| 个人指令 | ≤2000 字符 | AUTH-1006 超长 |
| 会话标题/项目标签 | ≤50 字符 | 自动截断 |

#### 11.3.2 Token、PAT 与锁定

- JWT HS256（claims: sub/role/exp/iat/jti），24h；禁用用户在 REST filter/WS 握手/任务下发三处校验，即时失效。
- **PAT（FR-16）**：设置页生成，格式 `gpat_<32位随机>`，仅创建时完整展示一次；可命名/吊销（吊销即时生效）；CLI 凭证文件 `~/.gill/credentials` 权限 600。
- 登录锁定：Redis 计数 5 次/15min，锁定文案与错密一致（不泄露状态）；成功登录清零。
- bcrypt(cost=10)；ADMIN 重置密码生成一次性临时密码并强制首登修改。

#### 11.3.3 认证错误码

AUTH-1001 用户名或密码错误；1002 用户名无效/已存在；1003 密码强度不足；1004 token 无效/过期；1005 账号已禁用；1006 PAT 无效或已吊销；1007 字段超长。

#### 11.3.4 会话状态机

```
created ──首任务──▶ sandbox_creating ──▶ active ──15min空闲──▶ idle ──再交互──▶ active(重建沙箱)
                      │(失败×3)            │(关闭/终止)                  │(30天不活跃)
                      ▼                    ▼                            ▼
                    error ◀────────── closing ──▶ closed            archived(只读)
   任务中断(agentd故障) → interrupted（可重发）
```

- 会话字段：id/user_id/title/project_tag/status/sandbox_id/node_owner/created_at/last_active_at/closed_at。
- 挂载项目标签后：project 级知识与该工作区 GILL.md 注入（FR-94/105）。

### 11.4 任务与执行规格

#### 11.4.1 任务生命周期

`queued（锁等待≤30s）→ running ⇄ awaiting_approval → done | failed | stopped | interrupted`

#### 11.4.2 预算矩阵（全部可配置）

| 项 | 默认 | 超限行为 |
|---|---|---|
| 轮次 MAX_ROUNDS | 25 | failed"已达轮次上限" |
| 单命令超时 | 60s | kill，工具结果标 timeout，Agent 可换法 |
| LLM 单次超时 | 120s | 退避重试 2 次后 failed |
| 任务总时长 | 15min | 强制 stopped |
| 工具连续失败 | 5 次 | failed（防死循环） |
| 审批等待 | 120s | 自动 deny，Agent 收"用户拒绝"继续 |
| 知识注入预算 | 8 条/2000 token | 超出按相似度截断 |

#### 11.4.3 审批流程（FR-38）

1. suggest 档 shell 执行前 risk.py 评估（附录 A 规则库）→ 命中即挂起并发 `approval_request{cid,command,riskLevel,reason,ruleId,expiresIn}`；
2. 响应 approve/deny/always_allow（按 ruleId 记会话内存白名单，会话内有效）；
3. 同时仅一个待审批；审计记 command/risk/rule_id/decision/decision_by/latency_ms；
4. auto→suggest 即时生效；suggest→auto 二次确认。

#### 11.4.4 终端回显与消息入库

- terminal 事件 stdout/stderr 双流分色（stderr 红），ANSI 透传，单条截断 8KB；
- 工具结果入库：stdout/stderr 尾部 32KB + sha256。

#### 11.4.5 沙箱生命周期

| 事件 | 默认 | 说明 |
|---|---|---|
| 懒创建 | 首任务/idle 后再交互 | <1s |

### 11.6 文件管理规格

#### 11.6.1 上传

申请（校验：属主/≤500MB/配额/类型管控/文件名净化）→ 预签名 PUT(15min) 直传（并发≤3，XHR 进度条）→ complete 时 HeadObject 核验+魔数复核 → UPLOADED+审计。PENDING 24h 未完成自动清理。文件名净化：拒 `../`、绝对路径、控制字符、>255 字节。

#### 11.6.2 同步进沙箱

手动或 Agent `materialize`；目标默认 `/home/user/uploads/{filename}`；同名默认覆盖（可选自动改名 `(1)`）；≤200MB；单用户并发 1/全局 10；8MB 缓冲流式；进度 5% 步进。

#### 11.6.3 导出/下载

文件树单文件或目录（打包 zip，≤200MB）；沙箱路径限 `/home/user` 内；预签名 GET 30min 可刷新。

#### 11.6.4 文件树

上传件+沙箱 `/home/user` 合并视图（云/盒图标区分来源）；深度≤6、单目录≤500 项；操作：刷新/删除/同步/导出/预览。

#### 11.6.5 在线预览（FR-69）

文本/md/代码（≤1MB 高亮渲染）、图片（直链缩放）、CSV（前 1000 行表格，分页）；其余显示元信息+下载按钮；预览走流式/直链不经应用内存。

### 11.10 知识库系统规格（FR-9x，核心）

#### 11.10.1 知识条目模型

```json
{
  "id": "kb_01H...",
  "user_id": 1, "scope": "user|project|session",
  "project_tag": "销售平台",            // scope=project 时必填
  "session_id": null,                    // scope=session 时必填，来源会话
  "type": "preference|fact|correction|project|snippet",
  "title": "Python 依赖管理用 uv",
  "content": "用户要求统一使用 uv 管理 Python 依赖，不要用 pip。",
  "tags": ["python", "工具偏好"],
  "source": "auto|explicit",             // Agent 自动沉淀 / 用户"记住"
  "source_msg_id": 12345,                // 溯源消息（可跳转）
  "embedding": vector(1024),             // 智谱 embedding-3
  "confidence": 0.9,                     // 显式=1.0；自动按上下文 0.6-0.9
  "hit_count": 3, "last_used_at": "...",
  "pinned": false, "status": "active|archived",
  "version": 2, "created_at": "...", "updated_at": "..."
}
```

类型语义：**preference** 用户偏好（工具/风格/口径）；**fact** 用户/组织事实（"周定义=周一到周日"）；**correction** 纠错记录（关联原错误行为）；**project** 项目知识（部署方式/结构/约定）；**snippet** 常用命令/代码片段。

#### 11.10.2 沉淀机制

- **自动沉淀（FR-91）**：系统提示内置沉淀准则（"当用户表达长期有效的偏好、纠正你的错误、给出项目事实时，调用 knowledge.save"）；每任务自动沉淀上限 5 条（防刷屏）；沉淀必须带 source_msg_id 与 confidence；工具调用过程在工具卡片可见（透明）。
- **显式沉淀（FR-92）**："记住 X" → 直接保存（source=explicit, confidence=1.0），跳过 Agent 价值判断；"忘掉 X" → `knowledge_search` 命中≥1 条时列出供用户确认（对话内选项卡），确认后删除并回复确认。
- **沉淀判定提示**：自动沉淀后在对话流出轻量提示条（§11.2.3）；用户可点"不该记"即时删除该条（反馈回路）。

#### 11.10.3 检索与注入管线（FR-93/BD-9）

1. 查询构造：当前任务文本 + 会话近 3 轮摘要 + 项目标签；
2. 混合检索：pgvector 余弦 top-20 ∪ 关键词/标签命中 top-20；
3. 过滤与排序：scope 优先级 session>project>user；pinned 置顶；confidence、hit_count 加权；90 天未命中降权（FR-96）；
4. 截断：top-8、总长 ≤2000 token；
5. 注入格式（system prompt 中的结构化块）：

```
[用户知识库]（检索到 6 条，按相关度）
1.（偏好）Python 依赖管理用 uv …
2.（项目·销售平台）部署：docker compose 起，入口 scripts/start.sh …
引用规则：使用任一条目时，在回复中自然说明依据（如"按你之前的偏好…"）。
```

6. 命中回写：被 Agent 实际引用的条目 hit_count+1、last_used_at 更新（判定=该条目 id 出现在引用标注中，由 loop 在轮次结束解析）。

#### 11.10.4 去重、版本与冲突（FR-95）

- 保存前用新内容 embedding 在同 scope+type 内检索，max similarity >0.92 → 判定为更新：写入新版本（version+1，旧版可回看），保留原 source 链；
- 0.80–0.92 视为相关但不同，正常新增但在知识库页"相关条目"互相引用；
- 用户编辑等同显式更新（version+1）。

|---|---|---|
| knowledge_save | title,content,type,tags,scope | 自动档每任务≤5 条 |

#### 11.10.6 知识库页面（FR-97）

- 列表：卡片流；筛选：作用域/类型/来源/标签；搜索框（走混合检索接口）；排序：最近使用/最近创建/命中最多；
- 条目卡：标题、内容摘要（3 行展开）、类型徽标、scope 徽标、来源（"对话沉淀·查看原会话"跳转 / "手动添加"）、hit_count、操作（编辑/删除/置顶/归档）；
- 顶部操作：[+ 添加知识]（表单：类型/scope/标题/内容/标签）、[导入]、[导出]（JSON/Markdown）；
- 版本历史：条目详情抽屉显示版本链与 diff。

#### 11.10.7 CLI 管理（FR-97）

`gill knowledge list [--scope --type --search] / add --type --title --content --tags / search "q" / rm <id> / export > kb.json / import kb.json [--merge-policy overwrite|skip|ask]`。

#### 11.10.8 导入导出（FR-98）

- 导出 JSON（含全部字段不含 embedding）/Markdown（按类型分节）；
- 导入按 (title, scope, type) 匹配：相似 >0.92 提示覆盖/跳过/并存（ask 逐条或策略化）；导入量上限 2000 条。

#### 11.10.9 性能与容量

- embedding 调用：仅沉淀/编辑时（非每轮）；检索 P95 ≤300ms（NFR-03）；
- 单用户 ≤2000 条（8002 提示归档导出）；pgvector 索引 hnsw(cosine, m=16)；
- 会话结束自动升格提示：session 条目被引用 ≥2 次时，任务结束提示"这条知识多次用到，升级为项目/用户级？"（一键升格）。

### 11.11 扩展能力体系规格（FR-10x，核心）

#### 11.11.1 五类扩展总览

| 类型 | 定义方式 | 执行位置 | 典型场景 |
|---|---|---|---|
| HTTP 工具 | 表单/OpenAPI 片段 | 沙箱内 curl（域名白名单） | 内部 API/第三方 SaaS |
| 脚本工具 | Python 脚本+参数 Schema | 沙箱内 python | 私有算法/格式转换 |
| 技能 Skill | SKILL.md 目录（Git/zip/内置） | 指导文档注入+资源落工作区 | SOP/最佳实践 |

| 提示词扩展 | 设置页文本 / 工作区 GILL.md | system prompt 注入 | 人设/全局要求 |

#### 11.11.2 manifest.toml（扩展包统一声明，附录 C 示例）

```toml
[package]
name = "ticket-tools"        # 唯一，[a-z0-9-]

display_name = "工单查询工具集"
```

#### 11.11.3 HTTP 工具（FR-101）

- 定义入口：扩展中心"新建 HTTP 工具"表单（可视化）或粘贴 OpenAPI 片段（解析 operations → 批量生成工具）；
- URL 模板支持 `{param}` 占位；参数类型 string/number/boolean/enum；
- 鉴权：header/query/bearer 三种，值存"密钥引用"（加密存储，编辑不回显）；
- 执行：agentd 将调用模板化成 curl 命令**在沙箱内执行**（统一审计与网络管控），响应体截 64KB 返回模型；
- 域名白名单校验：URL 域名 ∉ permissions.network → 拒绝（EXT-8102）并提示如何加白。

#### 11.11.4 脚本工具（FR-102）

- 上传单个 .py（入口 `def run(params: dict) -> dict|str`），可选 requirements.txt；
- 参数 JSON Schema 表单化，Agent 调用时校验；
- 首次使用在沙箱内建 venv 装依赖（依赖缓存于模板/卷，二次免装）；
- 返回：JSON/文本 stdout 直接回模型；产出文件落工作区（文件树可见）。

#### 11.11.5 技能 Skill（FR-103/BD-12）

- 目录规范（对齐业界）：`skill-name/SKILL.md`（frontmatter: name/description/when_to_use + 正文指导）+ 可选 `scripts/`、`resources/`；
- 安装源：内置官方技能（首批 5 个：CSV 分析、网页采集、PDF 摘要、正则生成、API 对接助手）、Git URL、zip 上传；
- 注入策略：仅 description+when_to_use 常驻工具清单；命中任务时加载正文（按需，控制 token）；`/skill 名称` 强制加载；
- 技能资源：安装时解压到工作区 `.gill/skills/{name}/`（会话沙箱内）。

#### 11.11.6 MCP 接入（FR-104/F10）

- 远程型：配置 displayName/端点（SSE 或 Streamable HTTP）/鉴权头；保存时执行 initialize+tools/list，成功则展示工具清单（名称/描述/Schema）；
- 工具面合入：`mcp_{server}_{tool}`；调用由 agentd 经 MCP 协议转发（结果截 64KB）；
- stdio 型（P1）：manifest 声明 command（如 `npx -y @mcp/github`），在沙箱内拉起并桥接；
- 健康检查：扩展中心每 60s 探活，离线标红并从工具面摘除，恢复自动回归。

#### 11.11.7 扩展中心页面（FR-106/109）

- 布局：左侧分类导航（全部/HTTP 工具/脚本/技能/MCP/提示词/已停用）；右侧卡片列表（图标/名称/版本/状态开关/工具数·近 7 天调用数）；
- 详情抽屉：manifest 预览、工具清单（含参数 Schema）、权限声明（域名/路径/密钥引用）、调用日志（最近 20 条，脱敏）、[测试运行]（FR-109：选工具→填示例参数→执行→展示请求/响应摘要）、[更新][卸载]；
- 安装向导：Git URL / zip / 表单三种入口；安装时解析 manifest→权限确认页（默认勾选声明的最小权限）→完成。

#### 11.11.8 安全模型（FR-107/BD-10）

- 所有 HTTP/脚本/stdio 执行发生在用户会话沙箱；web/agentd 容器零执行；
- 密钥库：用户级加密存储（AES-GCM，主密钥 env），manifest 仅存引用名；日志与前端永不回显明文；
- 出网白名单按扩展粒度；沙箱 DNS 出网仍受全局策略约束；
- 结果尺寸限制 64KB、超时 30s（可配 ≤120s）；
- 扩展卸载：删除配置与工作区资源；密钥引用保留（可手动清理）。

### 11.13 API 设计规范（FR 一等要求，"遵循常见规范"）

#### 11.13.1 REST 约定

- 版本化前缀 `/api/v1`；资源名复数 kebab-case（`/api/v1/sessions/{id}/messages`）；
- 方法语义：GET 安全幂等、PUT 全量替换、PATCH 部分更新、DELETE 幂等；
- 分页 `?page=1&size=20`（响应 `page/size/total/items`）；排序 `?sort=-created_at`；游标用于消息流 `?before=<seq>&limit=50`；
- 过滤显式白名单参数；不接受任意字段过滤；
- 幂等：写操作支持 `Idempotency-Key` 头（任务下发、上传申请）。

#### 11.13.2 错误响应格式（统一信封）

```json
{ "error": { "code": "TASK-3001", "message": "已有任务进行中",
             "detail": {"lockHolder": "task_a1"}, "traceId": "t-9f2c" } }
```

#### 11.13.3 WebSocket 协议（/api/v1/ws/agent）

- 握手：`?sessionId&token`（或 PAT）；文本帧=JSON 事件，二进制帧=投屏 JPEG；
- 信封：`{type, cid?, seq, ts, traceId, payload}`；服务端事件递增 seq，客户端重连带 `Last-Event-Seq` 增量重放；
- 心跳 25s ping/pong，3 次失踢出；
- 客户端→服务端：user_input/stop/preview_start/preview_stop/input_event/file_sync_in/file_export/file_list/file_delete/approval_response/kb_edit_hint；
- 服务端→客户端：agent_delta/tool_call/tool_result/terminal/screencast_meta/frame(二进制)/file_*/session_status/approval_request/approval_timeout/kb_captured/done/error/pong。

#### 11.13.4 OpenAPI 与文档

- web 导出 `/v3/api-docs`（springdoc），随代码同仓 `deploy/openapi.yaml` 提交；
- CLI `--json` schema 见附录 E.3，字段变更遵循 semver。

### 11.15 协作空间系统规格（FR-13x，v1.4 核心）

#### 11.15.1 数据模型

```sql
spaces(id PK, type 'personal'|'group', name, owner_user_id,        -- personal 每用户一条（注册时建）
       default_approval 'auto', default_op_mode 'free',            -- free|relay
       created_at, dissolved_at NULL)
space_members(space_id, user_id, role 'owner'|'admin'|'member',
       joined_at, PRIMARY KEY(space_id, user_id))
-- 归属改造：sessions.space_id；file_objects.space_id；knowledge_items.scope 增 'group'(space_id)；
-- extensions.visibility 'private'|'space'(+space_id)；space_chat(id, space_id, user_id, content, created_at)  -- 保留 30 天
invites(id, space_id, token, created_by, expires_at 24h, revoked BOOL, accepted_by NULL)
```

个人空间：注册即建（name=用户名，type=personal，仅本人）；协作空间：显式创建。所有既有资源外键从 user_id 迁移语义为 space_id（保留 user_id 作创建者溯源）。

#### 11.15.2 同步机制（FR-133/138）

- 复用既有总线：evt 流消费者组已支持"多 web 副本各自扇出"，扩展为"同会话多客户端本地扇出"——每副本维护本地订阅表，帧/事件一次入网多路下发（NFR-14：源端不感知观察者数量）；
- 在线列表：presence 扩展为 `presence:{spaceId}:{sessionId}`（成员→副本节点映射），会话头部头像列表显示；
- 协作轻提示事件：`presence_join/leave`、`op_lock_changed`、`member_typing`（节流 3s）、`nav_follow`（演示模式路径/URL 同步包）；
- 冲突串行化：input_event（浏览器回注）服务端按到达顺序排队下发 CDP；用户消息与会话锁规则不变（FR-37）。

#### 11.15.3 操作权令牌（FR-135）

- 键：`gill:oplock:{sessionId}`（Redis，值=userId，无 TTL 常驻+活跃续期）；
- 自由模式：无令牌，人人可操作（并发回注串行化）；
- 接力模式：申请→若空闲即获得（广播 `op_lock_changed`）；持有者释放/掉线 30s/无浏览器操作 2 分钟 → 自动释放并通知；
- 令牌不跨会话、不持久化（会话关闭即清）；切换模式由会话内任一成员发起（MEMBER 即可），有确认提示。

#### 11.15.4 共享资源语义（FR-136/BD-13）

- 空间文件库：file_objects 挂 space；任何成员可上传/下载/同步进任一会话；删除需上传者或空间 ADMIN；
- 组知识库：scope=group（space 绑定）；沉淀判定提示语区分"团队约定沉淀到小组/个人偏好沉淀到个人"（Agent 自动判断，可纠正）；检索优先级 session>project>group>user；
- 组扩展：发布（ADMIN 审）后 visibility=space；manifest/权限随包走；**密钥引用不随包共享**——各成员首次使用引导绑定自己的密钥（BD-14）；卸载空间级扩展仅影响自己（禁用），彻底移除需 ADMIN。

#### 11.15.5 成员聊天区（FR-137）

- 会话右侧/左侧可折叠侧栏：消息（头像+昵称+时间）；`@agent 内容` → 弹确认"转为任务输入"（或设置直接发送）；
- 与 Agent 对话流物理分区（不同底色/分组），避免混淆；保留 30 天，不入 messages 表。

#### 11.15.6 交接与演示（FR-139/140）

- `/handoff [备注]`：Agent 生成交接摘要（当前目标/已完成/待办/风险/关键文件路径）→ 存 group 知识（type=project, title="交接·日期"）+ 会话消息卡；空间首页显示"最近交接"；
- 演示模式：发起者本地导航事件（文件树路径、预览 URL、终端滚动位置）经 `nav_follow` 广播，跟随端平滑应用（滚动动画）；演示者退出即结束；同会话仅一个演示者。

#### 11.15.7 治理与生命周期（FR-141）

- 邀请：用户名直邀（即时生效）或链接（24h/可撤销/记录接受人）；人数上限 50/空间（可配）；
- 移除：即时断开其 WS、清除 presence、吊销空间内 PAT 上下文；其个人空间不受影响；
- 解散：OWNER 发起二次确认 → 会话关闭+沙箱销毁 → 知识库/文件库转只读 7 天（供导出）→ 物理清理；审计全程；
- 空间审计增强：command_audit 增加 space_id 与 actor（既有 user_id 即 actor）；成员变更/扩展发布/模式切换入审计。

#### 11.15.8 性能与容量（NFR-14）

- 单会话在线观察者 ≤10（超出拒绝并提示）；4 人同步实测口径：对话/终端 P95 ≤1s、投屏各端一致（同帧 ts 偏差 ≤500ms）；
- 扇出成本：帧发布一次，副本内多客户端共享（无 N 倍带宽）；多副本各自订阅 Pub/Sub；
- presence 心跳 10s，断线 30s 摘除。

## 附录 A：审批规则库 v1

**高危（high，必须审批）**：H1 `rm -[rf]` 递归删除；H2 `sudo/su` 提权；H3 `curl|sh` 下载即执行；H4 写 `/etc /usr /bin /boot /lib`；H5 `chmod 777/chown` 危险权限；H6 `iptables/ufw/systemctl stop`；H7 改 `~/.ssh/authorized_keys`；H8 `mkfs/dd of=/dev/`；H9 fork 炸弹；H10 `shutdown/reboot`。

**中危（medium，默认审批，ADMIN 可调免批）**：M1 包管理 install/uninstall；M2 `git push/clone` 外部仓库；M3 外网提交含凭据参数；M4 `find -delete`/单文件 rm；M5 kill 非自身进程；M6 crontab/at；M7 docker/systemctl restart；M8 `export` 环境变更。

> 规则仅作用于 shell 工具命令文本；浏览器/知识工具不审批；从宽设置（误报代价小于漏报）。
