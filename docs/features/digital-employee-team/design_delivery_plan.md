## 2. 建议实施顺序与任务契约

整体顺序：T01基础身份/事实 → T02模型协作贯穿 → T03监督控制/恢复 → T04知识模板采用 → T05项目与并行集成 → T06整合与切换。真实模型调用从T02开始参与整合，不等全部页面做完后第一次联调。业务团队无仓库场景与研发并行场景均为验证载体，不构成平台岗位/流程限制。

### T01 团队定义、身份和持久协议底座

- 来源：DET01/02/08/10/12、TR-01/02/06/07/09、ADR02～04；前提G及P01/P03的版本/采用表示明确。
- 目标：创建团队/模板/实际员工，保存组织树版本及独立监督约定；所有写操作具有身份、幂等键、版本条件和持久事件。
- 范围：拟新增Java controller/service/policy/repo/entity、迁移文件及共享wire schema；不改旧会话协议，不运行数据迁移。
- 输入/输出：设计§5/6/10管理接口及原始expected_revision → 对象/不可变revision或409；禁止Agent调用人类组织管理入口。
- 关键接口职责：submitCommand负责原子幂等与事件提交；saveDefinitionRevision负责CAS保存；claimWork负责租期/fence领取。内部拆分由开发决定，避免巨型函数和同层服务互调。
- 状态/副作用：同事务写领域状态、domain_event、durable_work；对象上传与DB引用分开处理失败。team关系保存串行短事务，防组合成环。
- 验证：真实PG两连接保存竞争、同key重试/不同payload拒绝、不同队引用、自指/成环、旧版本可读、写权限入口覆盖。共享schema供T02/T03消费。
- 完成产物：代码/迁移草案/程序测试及数据库竞争证据；交集成负责人后贯穿T02，不能只交表DDL宣告团队平台完成。
- 状态：实施中，负责人本次Codex。

### T02 动态协作、模型轮次与真实产物

- 来源：DET03/04/07/10/11/13、TR-02～04/06/09、ADR01/02/05/06；依赖T01契约、P02/P05及模型/执行环境门槛。
- 目标：用户群聊目标形成work_item/run，配置员工由模型自主派工、互相@、沟通和登记产物，能观察一次真实工具回执。
- 范围：拟新增agentd worker装配、gill_core团队协调/上下文/轮次/适配器、Java内部worker入口和Vue团队群聊/API/store。复用LLM/BaseSandbox，不能直接复用旧run_task作为可靠多员工运行器。
- 输入/输出：claim返回上下文引用、租约及执行凭证；轮次输出设计§7动作包；提交返回operation/state/revision/result_ref。模型输入必须验证实际system Prompt/Skills装配内容。
- 关键职责：prepareTurn形成确定上下文；executeTurn只完成一次流式模型请求；applyAction提交意图并驱动受控适配器；recordOutcome保存真实回执。低层不反调团队编排。
- 状态/副作用：LLM结束只是轮次结束；完成run须关联产物、检查和剩余问题。副作用意图/回执分开，未知不自动重试。
- 验证：真实模型收到不同员工Prompt和Skills；两个员工历史互不覆盖；无代码仓库业务任务产物可取得；消息commit先于正式完成事件；未执行工具不能被展示为通过。
- 员工互相@契约：引用系统设计§7.1，按稳定employeeId持久投递，消息/接收员工唯一；接收时校验团队与可见范围。验收覆盖无直属关系的双向@、多接收人、回复/任务关联、忙碌排队、暂停不恢复、无效/跨队对象拒绝及重投不重复应用；用户@我计数与员工收件分开。
- 完成产物：整合构建、实际请求/事件/产物引用、模型语义局限；交T03故障验证，不以模拟动作包替代真实模型集成。
- 状态：实施中，负责人本次Codex。

### T03 监督、逐级上报和控制恢复

- 来源：DET05/06/09、TR-04～06/08、P02/P05；依赖T01/T02。
- 目标：上级评估仍拿不准时逐级@用户，补证仍待解决；明确决定应用到受影响工作，暂停和停止在长任务期间可处理。
- 范围：decision/控制记录、独立listener、检查点/恢复及对账入口；Vue决策/证据/摘要接真实API。上级权力、独立任务继续范围不能由程序猜。
- 输入/输出：设计§8控制记录及§10决定/控制接口；answer返回answered，恢复应用另给applied_ref；停止返回请求记录及实际终态/未知。
- 关键职责：recordDecisionAnswer、requestControl、reconcileExecution、resumeFromCheckpoint分别处理答复、控制意图、外部对账和恢复；不把消息回复直接等价恢复。
- 状态/副作用：lease丢失拒绝旧worker推进；晚回执保留待核查；旧外部执行未结束时禁止再占同一写资源。
- 验证：运行中暂停/停止、暂停后回复、补证未决定、重复决定、错误自信/互评误判、模型/工具/持久化各阶段崩溃、Redis清空及消息重投。
- 完成产物：可定位的实际故障/恢复证据及剩余unknown；交集成负责人和独立测试。无有效取消/对账能力须返回设计，不能将其改成“停止成功”。
- 状态：实施中，负责人本次Codex。

### T04 员工知识与模板自迭代采用

- 来源：DET01/08/12/16、TR-01/02/07、P01/P03/P04；依赖T01～03。
- 目标：员工仅检索显式挂载源，人维护源新版本；模板可自行追加版本，按已定政策产生实际员工采用记录。
- 范围：知识追加/索引/检索、挂载guard、模板draft/revision/adoption和上下文追踪；新路径不得暴露旧knowledge_save或自动沉淀写权。
- 输入/输出：知识search读取employee/execution凭证 → 命中source/revision引用；template.revise携原基线/原因 → 新revision或冲突候选；采用形成独立记录。
- 状态/副作用：共享源更新不等于全部在途已用；卸载不能宣称清除模型已读内容；派生群聊/产物/模板访问按P04的有效决定验证。
- 验证：同队未挂载员工拒绝；另队显式挂同源可读；新员工不继承；旧版本保留；并发模板迭代不覆盖；Agent写知识经所有入口拒绝；回退不篡改历史。
- 完成产物：采用/读取链路及冲突、权限证据；实际模型迭代质量另交产品/测试验证。
- 状态：实施中，负责人本次Codex。

### T05 团队项目、并行工作区及版本集成

- 来源：DET14/15、TR-03/04/10、P06；依赖T01～04及V04/V08。
- 目标：团队多项目文档归档，两个需求并行、各自版本与基线可查，按授权集成后保留检查和结果。
- 范围：project/document/work_item/workspace/integration存储与服务；CubeSandbox工作区适配和可替换版本工具适配；团队详情/群聊项目库界面。provider选定后再细化实现，不能擅自开通托管账号。
- 输入/输出：设计§9工作区/集成契约；保存文档→不可变版本；集成(source,target_expected_ref,checks,授权引用)→真实结果、冲突或unknown。
- 状态/副作用：同需求多员工写也要隔离或串行所有权；目标ref移动使旧检查/合并前提失效；未知推送先查远端状态。
- 验证：同名文件并行无串写，产物/核查按版本读取；目标移动/冲突阻止无依据合并；超时后已推送不重复执行；无Git业务目标继续可用。
- 完成产物：真实版本工具/沙箱证据、provider限制、冲突恢复和并行需求整合构建。
- 状态：实施中，负责人本次Codex。

### T06 全链整合、兼容与运行观察

- 来源：全部适用AC、TR-01～10；依赖T01～05。
- 目标：交付可运行整合版本及独立测试/产品可验收证据，而不是各组件独立提交。
- 范围：组装团队工作台、真实员工运行、升级恢复、知识版本、并行产物、用量和异常投影；按设计§13实施兼容/切换计划，实际部署另按授权。
- 输入/输出：各任务同一版本契约及构建 → 整合commit、启动说明、运行证据、缺陷与未覆盖清单。拟定新API命令和实测命令随实现补齐，当前不虚构已有可调用端点。
- 验证：执行下述V01～12；Vue类型检查/build、相关Java/Python程序验证、API与浏览器完整路径；Python必须使用项目venv。终端/画面高频数据不走store；390×844不横向溢出。
- 完成：开发提供整合产物；独立测试给实际结果，产品对语义/可用交付验收。任一关键未知、失败或未决政策未闭环不能标整体通过。
- 状态：实施中；集成本次Codex，独立测试待安排。

每个任务交付均同步适用AGENT/设计/LLD；先核对已有相关测试基线，仅补本次逻辑有价值的验证。局部查询、内部辅助函数和组件拆分由开发按项目规范选择，不由本草案逐行规定。

## 4. 切换、恢复与交付

沿用系统设计§13新旧共存方案，先只读盘点存量、核对迁移版本和备份，再在授权测试环境验证升级/恢复，最后提交具体可评审发布方案。保留旧API/CLI与数据库字段语义，禁止未确认即把旧space自动变团队或知识自动挂载。

关闭新入口时先禁止新工作、核查活动执行及未知副作用；必须有真实操作入口、权限和回执后才能声称恢复完成。数据/外部副作用不能靠git revert恢复；失败保留记录，必要前滚。生产发布和数据处置不由本设计自动授权。
