## 修复与复测

1. 首轮测试先复现旧聊天标记会触发派工、工作项没有许可。这轮分离动作并由 Java 网关原子校验，加入真实请求重放。接口通过。真实模型纠错样例在一次调用内记录初审，却把「请修改」发成通知并收尾，v1/95 未修正。真实模型等待样例保持原文、无额外任务并形成待决，但只记录核查意见和沙箱回执，缺独立归档报告。首次结果保留。
2. 第二轮将通知工具命名为 notify_team，明确给出知会、核查、修改三个例子，旧工具仍按原请求重放。上报可带明确提交的 evidence 报告，先归档再上报；重复提交复用实际回执。审批须走完上级评估，在工作台显示许可状态。回归启动后发现 Java 持久化测试与模型 Worker 在同一测试库竞争领取，产生一例测试隔离失效；换到无 Worker 的独立测试库后 38 项通过。

第二轮 Python 35 项、前端 10 项、类型检查与生产构建通过。真实 HTTP/PG 21 条协议、8 条报告及收尾探针通过。Chrome 桌面和 390px 手机共 13 个场景通过，浏览器异常为 0。[桌面许可卡](../../../gui-test-screenshots/v20261118-dispatch-final-approval-desktop.png) · [手机许可卡](../../../gui-test-screenshots/v20261118-dispatch-final-approval-mobile.png)
