# 通用数字员工团队：快速交互原型 v0.7

日期：2026-11-17。依据：[基础设施需求分析 v0.7](../requirement_analysis.md)及 D36。本轮围绕工作台群聊完善决策上下文、交付证据和右侧工作摘要三项；[产品与系统联合评审](../requirement_review.md)的未决规则继续保留。

## 打开与体验

直接打开 [index.html](index.html)，无需安装、构建或后台。本机预览：[工作台](http://127.0.0.1:4173/?v=0.7#/overview)、[研发团队组织树](http://127.0.0.1:4173/?v=0.7#/team/dev)。版本参数用于避免旧资源缓存。

主入口保留**工作台 / 数字员工模板 / 团队 / 知识库**；本轮不新增独立运行记录或我的待办页面。工作台仍以对话为核心，团队状态在右侧，手机通过抽屉查看。

## 本轮三项交互

### 1. 在群聊中处理有上下文的 @我

- 决策卡展示具体问题、候选方案及示例代价、影响范围和需要用户决定的内容；展开后可看团队已有尝试及逐级上报意见。
- 打开卡片、查看上报经过或回到消息，不自动作出决定，也不清除尚未解决的 @我。
- 可选择具体方案或在原消息上下文回复；回复记录保留本次内容、影响和下一步。自由回复仅使用本地保守识别，不代表真实模型理解质量已经验证。
- “补充依据”“拿不准”等未形成明确取舍的回复保留为待处理；不因收到一条回复就把问题标为已解决。
- 明确回复只形成演示中的决定/回复记录，不证明员工已实际继续、工具动作成功或交付通过。团队已暂停时，回复不自动解除暂停；等待与恢复仍按后续有效规则设计。

### 2. 按版本查看交付内容与依据

- 群聊交付卡展示明确产物版本、示例检查、未验证范围和剩余问题，可展开查看内容及依据。
- 同一产物可切换历史版本并比较合成文本变化；评审对象对应具体版本，旧版结论不自动覆盖新版。
- 页面分别列出合成核查记录和真实执行检查。当前真实执行检查为零，没有进行真实模型、代码构建、数据核查、浏览器验收或外部操作。
- 研发示例明确区分方案说明与实现/测试证据；业务简报的示例复核也不替用户决定优先级。内容和比较均为演示，不代表正式交付验收。

### 3. 在右侧看团队工作摘要

- 团队摘要展示目标、当前进展、阻塞、下一步、来源和事实更新时间，并可定位相关消息或查看依据。
- **来源时间**表示合成工作记录的观测时间；**查看时间**表示用户最近一次查看本地记录的时间。重新查看不会把来源时间更新为当前，也不证明执行状态得到重新核实。
- 当前目标与快照不一致、缺少快照或数据过期时，明确显示未知/过期；不继续展示旧快照的忙闲统计，不将无数据推成空闲。
- 已知成员数量与工作忙闲状态分别处理。下一步是待执行安排的描述，不能据此判断工作已执行或恢复。

## 保留的 v0.6 组织树能力

团队详情保留组织树与节点详情：

- 以“我”为最终汇报根，员工显示姓名和开放岗位。本版单直属上级仅为演示形式，不固定岗位、层数或永久平台组织规则。
- 点击节点查看员工配置、知识挂载，并编辑直属上级和本团队分工；拖到另一位员工下或根节点可调整汇报关系。
- 拖动和选择上级先修改草稿，支持撤销、重新读取及明确保存；未保存不改变源关系，源关系或成员变化时不覆盖新内容。
- 自身、后代、跨团队或无效上级不能保存；缺失、循环关系显式提示待修复，不自动归根。空团队保留创建员工入口。
- 手机可查看树并通过选择上级/保存完成等效操作；未声称触屏拖拽已完成验证。

组织树用于汇报与逐级评估，监督关系独立，不据此固定任务执行顺序。保存不会移动员工团队归属、修改模板 Prompt，或证明在途工作已采用新层级。对话模板、自迭代历史、员工只读知识、团队项目库和多需求并行版本等既有演示继续保留。

## 本地演示与评审边界

全部为隔离静态 HTML/CSS/JavaScript 和浏览器内存中的合成数据；刷新/重置恢复初始状态，没有后台、数据库、真实模型、知识检索/RAG、Git 或沙箱执行，也没有更改生产服务。

卡片、版本比较、回复回执、状态切换和保存只改变本地演示数据。知识仍按实际 employeeId 显式挂载，Agent 只读；模板自迭代演示不自动同步既有员工。组织/模板/知识的历史、权限检查、并发和恢复均未经过真实后端验证。

联合评审 R-01～R-04 继续有效：模板/组织版本采用、监督和升级等待恢复、知识派生内容可见范围、自主运行成本/停止后果及真实执行隔离/集成仍需明确。三项展示优化不替代这些业务决定或技术契约，静态交互评估不能证明整体已达开发交接条件。

## v0.7 轻量走查与复评状态

Chrome headless 通过 CDP 操作实际页面，覆盖 1440×1040 桌面与 390×844 手机视口，并核对本地演示状态；19 项关键路径及 3 项修正复查通过，未观察到脚本异常。这是静态原型轻量走查，未执行真实业务 E2E、模型理解或外部工具核查。

- 查看决策/证据不清除 @我；补充依据仍待处理；明确选项形成范围和下一步回执，其他 @仍保留，暂停不自动恢复。
- 核对历史版本、检查对象和失败记录；不跨团队引用证据，不把研发方案说明当作代码/测试结果。
- 构造过期/未知快照，检查旧统计隐藏、源时间保留和查看时间分开；空闲团队的新目标不凭消息推算已执行进度；空团队保留目标后创建员工，摘要转为待核实，不继续显示无人。
- 修复手机定位消息后状态抽屉未收起的问题，并复查消息定位、决策和证据抽屉；两种视口均无页面横向溢出。
- 决定回执将之前的等待表述标为“原等待范围”，避免已决定事项仍被当作当前等待。
