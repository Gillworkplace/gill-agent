## 缺陷与回归

| 实际复现 | 修复和复验 |
| --- | --- |
| 审批后重复知会和单独收尾吃完 8 次额度，复核无法开始。首个复合参数还漏传了交接类型。 | 收尾工具接受一项明确的派工或核查；报告、交接、完成分步骤留实际回执。独立字段区分两种交接，避免重复知会。失败后已有交接可查，真实请求重放只产生一个任务。 |
| 租约失效后任务显示待核实，运行仍显示进行中。核实后任务显示排队，却没有可领取的执行。 | 任务、运行和关联集成同步显示事实。等待明确恢复，已核实的执行可获得新的调度代次。真实 PostgreSQL 测试断言已创建可领取工作。 |
| 云端集成丢失回执后，集成依旧排队。同一来源在原动作未核实时也能发起新集成。正常集成又把已完成源任务变回待跟进。 | 未知动作先核实。保留旧集成及原基线，再通过明确的新请求执行真实检查和 CAS。集成继续保留源任务已完成状态。 |
| 未填写限额的旧配置向模型传递空值，使有效模型请求在发送前失败。 | 沿用平台默认 25 次及 900 秒装配运行上下文。重新执行两次真实请求，验证旧快照、新版本及真实返回用量。 |
| 首次云沙箱验证与主实例清理器共用资源池，隔离库沙箱被清理。 | 保留该次设施失败。随后在清理窗口之间完成独立资源验证，按新库重启、查询和回收流程重测。 |

费用核实采用供应商实际 token 回执。货币账单、长期成功率、大容量压测和任意自由文本的语义防泄漏保证不属于本轮已批准验收判据。实际主服务发布与这些测试结论分别记录。

最终程序验证 Java 40 项、Python 39 项、前端 10 项，类型检查和生产构建通过。真实 HTTP/PG 回归 22 项、报告与交接重放探针 9 项、浏览器基础回归 13 项通过，另有浏览器真实模板采用、云端状态、同版本失败证据的补测。最终空白项目用 7 次调用完成源码、测试和归档，Git 检查返回 0 并实际更新项目基线。最后一组云端回执丢失验证了核实前重复集成被拒绝，核实后新请求通过实际检查并完成。逐项记录见[原验收矩阵](reacceptance_20261118.md#v11-最新验收矩阵)及[结构化证据](full_acceptance_evidence_20261118.json)。
