# 团队 Skill 配置设计 v0.1

需求依据为 D44，流程、角色、成员三层由用户提出。适用对象是团队管理者本人。[打开交互原型](prototype/skill-configuration/index.html)

## 配置与生效

| 层级 | 管理者在哪里操作 | 作用范围 |
| --- | --- | --- |
| 团队流程 | 在「团队流程」编辑唯一的 Prompt，可导入多个目录 | 全队共用。流程描述如何交接、复核和上报，保存时无需选人 |
| 团队角色 | 在「团队角色」创建自定义角色、修改角色 Prompt 和 Skill | 同队采用该角色的成员共用。角色详情显示当前采用成员，修改角色即更新共用规则 |
| 成员 | 在「成员」打开个人配置，关联角色并编辑个人 Prompt 和 Skill | 只有该成员采用这份个人配置。角色关联和个人配置一起保存 |

在任一入口可以按成员查看生效预览。预览展示团队流程、角色和个人配置的来源、版本和文件用途。三层的同名文件各自保留。每个目录允许多个 Skill，继续采用 D43 的路径和用途规则。已有数字员工模板继续作为可复用的创建来源，成员在团队内采用的个性化配置遵循 D38。

配置权限沿用既有团队管理约定。组织树继续表达直属上报关系。群聊默认接单人与运行额度属于运行设置。角色用于采用共用指令。

## 关键交互与边界

- **流程更新。** 保存显示新版本和覆盖成员数。首次使用可以直接录入文字或导入目录。已有任务按创建时的快照继续，新任务采用当前流程。
- **角色复用。** 创建角色后，到成员卡片关联。角色详情显示使用该角色的成员。保存前提示影响人数。成员换角色后，预览切换角色来源，其个人 Skill 及在途任务快照保留。
- **个人配置。** 成员可查看自己采用的三层。编辑时显示独立的个人目录，以及本次所选角色。文件可调整用途和移除，取消会放弃本次未保存编辑。
- **兼容与异常。** 首版采用一个可选角色。已有成员可保持无角色，并保留原有分工、模板与个人配置。模板文件和文本 Skill 可在预览中展开。角色名称在同一团队内唯一。原型和本次实现覆盖新增、修改、关联及解除关联。
- **指令冲突。** 预览保留每条指令的来源。团队流程描述跨人协作约束，角色与个人 Skill 补足职责和方法。模型发现实质冲突时按已约定的直属上报路径处理。平台硬约束继续由现有校验机制执行。

## 竞品对比与产品优势

对比任务为「给两位成员统一工作规则，同时保留各自的能力」。

| 对比 | 已核实做法 | 对 Gill 设计的启示 |
| --- | --- | --- |
| CrewAI | Crew 组织 Agent、任务与执行过程，Agent 独立定义角色、目标和能力。 [Agents](https://docs.crewai.com/en/concepts/agents) · [Crews](https://docs.crewai.com/en/concepts/crews) | 共用流程与单个执行者的职责应能分别维护。 |
| Claude Code | 项目指令可集中管理，自定义 subagent 有独立指令并可预加载 Skills。 [项目指令](https://code.claude.com/docs/en/memory) · [自定义 subagent](https://code.claude.com/docs/en/sub-agents) | 保留清楚的配置来源，便于排查实际执行依据。 |

Gill 方案的预期收益在于将团队内的角色视为独立、可由多名成员采用的配置。管理者更新一次岗位要求，并能逐人核对完整生效版本。当前证据覆盖原型交互，后续需在真实任务中验证。

## 验收场景

| 场景 | 验收判据 |
| --- | --- |
| 配置团队流程 | 管理者无需选择成员即可保存。已有成员的新任务预览均引用新版流程。 |
| 创建或更新角色 | 两名关联成员可见相同角色版本。其他角色及未关联成员的预览不出现这份角色内容。 |
| 改一位成员的 Skill 或角色 | 只更新该成员的后续任务预览。角色切换保留个人目录。 |
| 回看使用依据 | 流程、角色、成员可分别查看来源、版本、文件与用途。修改配置后，示例在途任务仍显示原快照。 |
| 导入目录 | 三层均支持导入，保留相对路径。确认保存才更新预览，取消恢复进入编辑前的状态。 |

原型使用通用占位信息，所有操作在当前页面内模拟。用户随后要求按原型还原。正式实现采用可选单角色，并在个人配置中呈现模板继承。真实运行和预览契约见[实现说明](implementation.md)，开发验证见[测试记录](../../03-test-cases.md#2313-团队-skill-三层配置开发回归2026-11-19)。

## 设计走查

通过本地文件在 Chrome 的 1440 与 390 像素视口走查了三个配置页、目录导入、保存与取消、角色创建与关联、同角色成员同步采用、成员保留个人 Skill，以及新任务和在途快照的切换。检查过程中修正了关闭后立即重开编辑时的状态清理顺序，复查通过。产品视角检查了三个入口的覆盖范围，以及配置全队流程无需选人的操作路径。
