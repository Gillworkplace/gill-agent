候选二允许在批量上报前保存同时提交的新报告，原产物更新不从复合完成请求中提前提交。报告保存及任务结束各自留有明确回执。两种实际失败响应顺序均在真实 HTTP/PG 环境重放，结果都为 1 项阻断任务、1 条待决及 1 份报告，没有误派工。综合程序回归 Java 35、Python 32、前端 9，类型检查和构建通过。原协议 A/B/G 与 X01/X02、补充知识 Y01/Y02 通过，收尾协议 6 条通过。服务未接收追加模型额度的请求。

工作台补齐可追溯信息。决策详细信息展示本任务范围、实际尝试、选项及两级已记录意见，缺少单独代价时给出真实缺项。请求失败后显示过期，保留最后读取时间并将忙闲标为未知。任务详情显示冻结的团队、员工、模板与 Skill 版本，以及执行器实际读取的知识版本和共享源当前版本。最新构建上真实桌面及 390 px 手机验证通过，包括临时阻断浏览器请求后恢复，以及打开卡片未改变决定。原 12 个浏览器场景完成复测。

补测跨团队两个显式挂载员工分别读取最新版，未挂载员工无读取。测试了员工卸载后试图复制已读知识正文、跨团队模板新版本未授权/已授权的状态，均符合原政策。真实本地 Git 与实际 `TeamGit` 适配器发生内容冲突，保留目标 HEAD，取消进行中的合并，未运行配置检查，未推外部仓库。此例本地执行 Git，存储读取用真 bundle 字节，未执行云环境下的未知合并恢复。

## 仍开放的事项

R07 的原未收尾症状在候选一首组和候选二纠错试验中未复现。候选一第二组的版本跳变、报告保存失败均保留。原问题需要随 R08 最终候选再在同一构建复测，不能用历史成功关闭全部模型分支。

R08 跨轮根因已有真实回执。模型第 2 轮在知道要等待时请求对端“知悉并确认”，仍给 `requiresResponse=true`。当时服务端没有可执行的先决条件；第 3 轮才收到 `ask_superior`。P02 对已有决定的阻断正常。在任意 Prompt 语义下，对可能依赖尚未提出的决定实行强制拦截，需要明确规则何时启用、作用于什么任务。已向用户提出可选「派工前需决定」边界，等待明确决定。项目仍保持原验收门槛和 27 项缺口索引，本轮只补上述有证据的分支。尚未执行的空白代码项目、完整真实 GUI 两轮模板创建采用、真实多级模型语义、云端未知集成恢复及其他原矩阵缺口继续按原判据追踪。

后续用户已确认改造群聊动作与可选派工审批，决策和新一轮记录见[派工流程修改与回归](dispatch_approval_feedback_20261118.md)。以上为确认前的历史观测。
